Konzept: Warum dieses Setup?

Cursor ist eine KI-gestützte IDE, die durch einen eingebauten Agenten Code erzeugen, refaktorieren und prüfen kann. Damit der Agent nicht bei jedem Auftrag neu eingewiesen werden muss und konsistent nach den Projektstandards arbeitet, gibt es drei Mechanismen:

Rules
Immer im Kontext
.mdc-Dateien in .cursor/rules/. Werden beim Öffnen passender Dateien oder immer geladen. Der Agent handelt danach, ohne dass du ihn explizit darum bitten musst.
Skills
Auf Abruf nachladen
Ordner mit SKILL.md in .cursor/skills/. Tiefer gehendes Fachwissen, das nur geladen wird, wenn es gebraucht wird – spart Kontext-Budget für die eigentliche Aufgabe.
Hooks
Ereignis-getrieben
Scripts und Prompt-Hooks in .cursor/hooks.json. Laufen automatisch bei Session-Start, Dateibearbeitung oder Session-Ende – ohne manuellen Aufruf.
Lernhinweis: Das Setup ist selbst dokumentierter Code. Jede Rule, jeder Skill und jeder Hook lässt sich im Editor neben diesem Dokument öffnen. Pfade beginnen immer mit .cursor/ im Projekt-Root.

Rules – persistente Leitplanken

Rules werden als .mdc-Dateien in .cursor/rules/ abgelegt. Jede Rule hat einen Scope: entweder alwaysApply: true (immer aktiv) oder ein globs-Muster (aktiv, wenn eine passende Datei geöffnet ist).

Datei Scope / Trigger Inhalt / Zweck
project-conventions.mdc alwaysApply Monorepo-Struktur, Namenskonventionen, Security-Grundregeln, API-Prefix /api/, Dependency-Management
project-architecture.mdc alwaysApply Architekturentscheidungen (nvm als Shell-Funktion, 127.0.0.1-Binding, Signals statt NgRx, zweischichtiger Injection-Schutz), Datei-Quickref
nvm-security.mdc alwaysApply Whitelist erlaubter nvm-Befehle, Versionsmuster-Regex, Single-Quote-Escaping, was niemals erlaubt ist (kein eval(), kein /api/exec)
comments-english.mdc alwaysApply Alle Code-Kommentare (Inline, Block, TSDoc) müssen auf Englisch sein – in allen Dateitypen (.ts, .html, .scss, .sh)
angular-standalone.mdc apps/web/**/*.ts
apps/web/**/*.html
apps/web/**/*.scss		 Standalone Components, Signals, HttpClient, SCSS-Konventionen; enthält eigenen Accessibility-Abschnitt (WCAG 2.1 AA, aria-labels, live regions, Fokus-Management)
express-api.mdc apps/api/**/*.ts Router-Struktur, typisierte Request-Handler, zentrales Error-Middleware-Pattern, Security-Hinweise, Response-Format
nodejs-typescript.mdc apps/api/**/*.ts Async/Await, execFile('bash',['-c',…]) für nvm, Custom Error Types, Env-Variablen, tsconfig-Einstellungen
testing.mdc apps/**/*.spec.ts
apps/**/*.test.ts
apps/**/*.e2e.ts		 Vitest + Supertest (API), @testing-library/angular (Web), Playwright (E2E), vi.mock()-Konvention, Naming-Regeln
formatting.mdc apps/**/*.ts
apps/**/*.html
apps/**/*.scss
*.json · *.mjs		 Prettier-Konfiguration (100 Zeichen, Single Quotes, LF), ESLint Flat Config für API und Web (angular-eslint), EditorConfig, npm-Scripts
a11y.mdc apps/web/**/*.html
apps/web/**/*.ts		 WCAG 2.1 AA: accessible button names, aria-hidden auf SVGs, Tabellenstruktur mit scope, aria-live-Regionen, Modal-Anforderungen, .visually-hidden
commit-conventions.mdc alwaysApply Conventional Commits: 10 Typen (feat/fix/perf/refactor/test/docs/chore/style/a11y/ci), 7 Scopes (web/api/e2e/a11y/deps/hooks/rules), Imperativ-Stil, max. 72 Zeichen, Beispiele + Anti-Patterns
performance.mdc apps/web/**/*.ts
apps/web/**/*.html

Zusammenspiel commit-conventions + stop-Hook: Die Commit-Konventions-Rule ist alwaysApply. Der stop-Hook prüft am Sitzungsende in Punkt 7 der Checkliste automatisch, ob die geplante Commit-Message dem Conventional-Commits-Format entspricht.
Wie Rules geladen werden: Rules mit alwaysApply: true sind in jeder Antwort des Agenten präsent. Glob-basierte Rules werden automatisch aktiviert, sobald eine passende Datei im Editor geöffnet ist oder der Agent sie bearbeitet. Es gibt keine manuelle Aktivierung.

Skills – situatives Expertenwissen

Skills sind Ordner in .cursor/skills/, die je eine SKILL.md (und optionale Referenz-Dokumente) enthalten. Sie werden nur geladen, wenn der Agent sie aufruft – typischerweise weil der Auftrag in das Beschreibungsfeld passt. So bleibt das Kontext-Budget für Rules + eigentliche Aufgabe reserviert.

project-explainer
Detaillierte Erklärung der Architektur, Designentscheidungen, Angular-Komponenten, Express-Backend und Datenfluss.
  • „Wie funktioniert X?" / „Erkläre die Architektur"
  • „Was macht dieser Dienst?" / „Warum so gebaut?"
  • „Wie kommuniziert Frontend mit Backend?"
angular-expert
Angular 17+ Standalone, Signals, HttpClient, reaktive Muster, SCSS-Architektur, Routing und Template-Kontrollfluss.
  • Angular-Komponenten implementieren oder debuggen
  • Signal-basiertes State-Management
  • HTTP-Fehlerbehandlung, Lazy Loading, SCSS
nodejs-express-expert
Express-Routen, typisierte Handler, Child-Process-Management, SSE-Streaming, Fehlerbehandlung und TS-Konfiguration.
  • API-Routen bauen oder Middleware schreiben
  • nvm Shell-Befehle ausführen / SSE streamen
  • Error-Middleware, Input-Validation
formatting-linting-expert
Prettier-Konfiguration, ESLint Flat Config für TypeScript und Angular, angular-eslint-Regeln, EditorConfig, Lint/Format-Scripts.
  • ESLint/Prettier einrichten oder Fehler beheben
  • angular-eslint-Regeln konfigurieren
  • Format/Lint-npm-Scripts hinzufügen
testing-expert
Vitest Unit Tests, Supertest Integration Tests, Angular Component Testing, Playwright E2E, nvm-Mocking, Coverage-Konfiguration.
  • Tests schreiben oder Test-Infrastruktur aufsetzen
  • Fehlgeschlagene Tests debuggen
  • child_process mocken, Coverage konfigurieren
documentation-expert
TSDoc/JSDoc für TypeScript, OpenAPI/Swagger-Annotationen, swagger-ui-express, Markdown-Benutzerhandbuch.
  • Code-Kommentare / TSDoc schreiben
  • API-Endpunkte mit @openapi dokumentieren
  • Benutzerhandbuch oder README aktualisieren
debugging-expert
Debugging aller Schichten: Angular Signals (DevTools, effect()-Traces), Express child_process stderr, SSE-Streaming-Diagnose, häufige nvm-Laufzeitfehler und Vitest-/Supertest-Fehlermuster. Inkl. Quick-Diagnostic-Checkliste.
  • Signal aktualisiert sich nicht wie erwartet
  • nvm-Befehl schlägt still fehl (kein Output, falscher Exit-Code)
  • SSE streamt nicht oder bricht ab
  • Test schlägt unerwartet fehl (vi.mock() nicht aktiv, Port-Konflikt)
  • „Wie debugge ich X in diesem Projekt?"
refactoring-expert
Code-Smell-Erkennung für Angular und Express, Entscheidungshilfen für Komponenten-/Service-Extraktion, sicheres Umbenennen und Verschieben von Dateien, Test-Coverage-Erhalt bei Umstrukturierungen, Typ-Alignment zwischen Frontend und Backend.
  • „Sollte ich das in eine eigene Komponente auslagern?"
  • Komponente wächst auf > 200 Zeilen
  • Logik ist in mehreren Komponenten dupliziert
  • Datei umbenennen oder verschieben ohne Import-Brüche
  • Code-Review vor einem PR
a11y-expert
WCAG 2.1/2.2 AA für Angular: ARIA-Rollen, Keyboard-Navigation, Fokus-Management (CDK), Live-Regionen, zugängliche Tabellen, Modals und Buttons. Enthält eine komponentenweise CHECKLIST.md.
  • Angular-Templates auf WCAG 2.1 AA prüfen oder verbessern
  • aria-*-Attribute oder Fokus-Trap implementieren
  • A11y-Linter-Fehler beheben, CDK A11yModule einrichten
  • Komponentenaudit gegen Checkliste durchführen
Eigene Skills erstellen: Der Cursor-eigene Skill create-skill (~/.cursor/skills-cursor/create-skill/SKILL.md) führt durch den Prozess. Projektspezifische Skills kommen nach .cursor/skills/, persönliche Skills (projektübergreifend) nach ~/.cursor/skills/.

Hooks – automatische Qualitätssicherung

Hooks sind in .cursor/hooks.json konfiguriert. Sie laufen bei definierten Ereignissen der Agent-Session und können den Agenten ergänzend informieren, warnen oder auffordern, weitere Schritte auszuführen. Es gibt zwei Typen: Command Hooks (Shell-Skripte, die JSON über stdin/stdout tauschen) und Prompt Hooks (Anweisungen für den Agenten selbst).

sessionStart Prompt
Projekt-Kontext-Injection
Lädt beim Sitzungsstart die Architektur-Zusammenfassung (nvm als Shell-Funktion, Komponenten-Übersicht, Security-Hinweise) und listet alle verfügbaren Skills. Sorgt dafür, dass der Agent von der ersten Antwort an über das Projekt informiert ist.
beforeShellExecution Script × 2
security-check.sh
Läuft vor jedem Shell-Befehl. Prüft auf riskante Muster (Netzwerk-Tools wie curl|wget, eval, sudo, rm -rf) und fragt den Nutzer um Bestätigung. failClosed: false.
npm-guard.sh neu
Matcher: npm (install|add|update). Blockiert hart auf @latest-Tag (Konventionsverletzung). Fügt bei allen anderen Package-Operationen einen Reminder ein: Caret-Range prüfen, knip laufen lassen, npm audit ausführen.
afterFileEdit Script × 3 matcher: Write
post-edit-notify.sh
Allgemeine Nachricht nach Dateispeicherungen. Gibt dem Agenten Kontext über die soeben geänderte Datei zurück.
lint-reminder.sh
Pfad-basiertes Routing: .spec.ts → Vitest-Hinweise, apps/api/*.ts → Backend-Lint-Tipps, apps/web/*.ts → Angular-Lint + CDK a11y, apps/web/*.html → 7-Punkt-A11y-Checkliste für Templates.
a11y-check.sh neu
Statischer Grep-Scan für apps/web/**/*.html. Prüft auf: fehlende aria-label an Tabellen-Buttons, SVGs ohne aria-hidden, Tabellen ohne scope/aria-label, Dialoge ohne cdkTrapFocus, fehlende aria-live-Regionen, Fehler-Signale ohne role="alert".
stop Prompt × 2 loop_limit: 1
Qualitäts-Checkliste
Prüft nach Abschluss: (1) TSDoc-Kommentare auf neuen Methoden, (2) @openapi-Annotationen auf neuen Endpoints, (3) Unit-Tests für neue Logik-Einheiten, (4) TypeScript-Lint-Fehler (no-explicit-any, no-floating-promises), (5) A11y: accessible names, aria-live-Regionen, Tabellen-scope, SVG aria-hidden, (6) Performance: OnPush, stabiles track in @for, keine Funktionsaufrufe in Templates, (7) Commit-Format: Conventional Commits eingehalten? Informiert den Nutzer über noch offene Punkte.
Changelog-Update
Liest CHANGELOG.md und fügt Änderungen automatisch unter [Unreleased] ein – gruppiert nach Added / Changed / Fixed / Removed. Nur nutzerrelevante Änderungen; reine Refactorings ohne Verhaltensänderung werden nicht protokolliert.

Session-Flow: Zusammenspiel

Das folgende Ablaufdiagramm zeigt, wie Rules, Skills und Hooks in einer typischen Arbeits-Session ineinandergreifen:

sessionStart ──► Prompt-Hook injiziert Projekt-Kontext + Skills-Übersicht
↓
Nutzer stellt Aufgabe
↓
Rules geladen ──► 4× alwaysApply (immer) + Glob-Rules für geöffnete Dateien
↓
Skill aufgerufen? ──► z. B. a11y-expert → SKILL.md + CHECKLIST.md geladen
↓
Shell-Befehl ──► beforeShellExecution: security-check.sh prüft Muster
npm install/add → npm-guard.sh: @latest blockiert · knip/audit reminder
↓
Datei gespeichert ──► afterFileEdit: post-edit-notify + lint-reminder + a11y-check
*.ts (api) → Backend-Lint-Hinweis
*.ts (web) → Angular-Lint + CDK a11y Hinweis
*.html → 7-Punkt-A11y-Grep-Scan
↓
stop ──► Qualitäts-Checkliste (TSDoc, Tests, Lint, A11y, Performance, Commit-Format)
↓
stop ──► CHANGELOG.md automatisch aktualisieren

Die folgende Tabelle zeigt, welches Werkzeug bei welcher Art von Arbeit greift:

Aufgabentyp Rule Skill Hook
Angular-Komponente implementieren angular-standalone, a11y angular-expert lint-reminder + a11y-check
API-Endpunkt hinzufügen express-api, nvm-security nodejs-express-expert lint-reminder + stop-Checkliste
Tests schreiben testing testing-expert lint-reminder (spec-Hinweise)
A11y-Verbesserungen (Templates) a11y, angular-standalone a11y-expert + CHECKLIST.md a11y-check.sh + stop-Checkliste
Dokumentation schreiben comments-english documentation-expert stop: TSDoc + @openapi geprüft
Performance-Optimierung performance, angular-standalone refactoring-expert stop: OnPush + track geprüft
Debugging (Signal, SSE, nvm) project-architecture debugging-expert –
Refactoring / Code-Review project-conventions, performance refactoring-expert stop: Lint + Tests + Commit-Format
Dependency hinzufügen project-conventions, commit-conventions – npm-guard: @latest blockiert + knip/audit
Git Commit erstellen commit-conventions – stop: Commit-Format (Punkt 7)
